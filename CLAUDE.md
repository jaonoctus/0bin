# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project status

0bin is a client-side encrypted pastebin (Python port of sebsauvage's ZeroBin). Per the README, the
public 0bin.net instance is dead, the domain was taken over by scammers, and upstream does not accept
PRs. The code remains for self-hosting. Requires Python 3.7+. Licence: WTFPL.

## Commands

There is no test suite, no CI, and no linter configuration beyond `.pylintrc` and `.editorconfig`
(4-space Python, 2-space HTML/JS/CSS).

```bash
# Install for development (runtime deps from setup.cfg, build tooling from dev-requirements.txt)
pip install -e .
pip install -r dev-requirements.txt      # doit, pyScss, twine

# Run the dev server (auto-reload, unminified assets, prints the admin URL)
python -m zerobin --debug true
# or, after `pip install -e .`:
zerobin runserver --debug true --host 127.0.0.1 --port 3255

# Other CLI subcommands (clize; `runserver` is the implicit default)
zerobin infos                          # prints admin URL, data dir, config dir, static dir
zerobin set-admin-password <password>
zerobin delete-paste <id-or-url> [...]
zerobin clean-expired-pastes --dry-run --verbose

# Rebuild minified assets (needs `uglifyjs` on PATH and the pyScss module)
doit compress          # runs compress.sh -> static/js/main.min.js, static/css/style.min.css
./compress.sh          # same thing, directly
./vendor_noble_ciphers.sh   # rebuild static/js/noble-ciphers.js from npm (needs node)

# Packaging / release (see dodo.py)
doit build             # compress + generate MANIFEST.in + bdist_wheel into dist/
doit build_pyz         # shiv single-file executable dist/zerobin.pyz
doit bump_version      # interactive; must be on master, clean, and up to date
doit release_to_pypi   # bump_version + build + twine upload
```

```bash
# Docker (Dockerfile + docker-compose.yml)
docker compose up -d --build              # http://localhost:3255
docker compose exec zerobin python -m zerobin infos
docker compose exec zerobin python -m zerobin set-admin-password <password>
```

**Python 3.10 to 3.11 only.** bleach 6.x needs 3.10+, and the app's own `distutils` imports
(`strtobool` in `cli.py` and `routes.py`) break on 3.12. `setup.cfg` pins `sigtools<3`
because clize 4.1.1 holds attrs at 19.x while letting sigtools float to 4.x, which needs
attrs 20+ and crashes at import. A plain `pip install .` (non-editable) yields a broken
package: `package_data` in `setup.cfg` lists `view/*` (typo) and omits `VERSION`, and the
`MANIFEST.in` that would fix it is generated by `doit` and gitignored. Use `pip install -e .`.

Dependency pins were audited with `uvx pip-audit` in September 2026 and are clean. Beaker
sessions use `session.data_serializer: json` in `routes.py` to avoid pickling session data
(CVE-2013-7489); Beaker's file backend still pickles its own outer envelope.

Only `runserver` reads `ZEROBIN_DATA_DIR` / `ZEROBIN_CONFIG_DIR`. `infos`,
`set-admin-password`, and `clean-expired-pastes` (without flags) fall back to appdirs, so
they can point at different directories than the running server. The Docker image sets
`XDG_DATA_HOME` and `XDG_CONFIG_HOME` so both paths agree.

`doit` with no arguments runs `compress`. Because the docs folder predates the 1.x rewrite,
`docs/en/options.rst` and `docs/example_settings.py` describe CLI flags and settings
(`--settings-file`, `--compressed-static`, `USER`, `TEMPLATE_DIRS`, ...) that no longer exist.
Trust `zerobin/cli.py` and `zerobin/default_settings.py` over the docs.

## Architecture

**Server side (Bottle, no database).** `zerobin/routes.py` defines all routes on a `Bottle()`
app and then wraps it in Beaker `SessionMiddleware` (file-backed sessions, used only for admin
login). Importing `routes` calls `ensure_app_context()` at module import time, so settings and
directories exist before any route is registered. `get_app()` is the entry point used by both
`cli.py` and `wsgi.py`; it re-runs `ensure_app_context` with explicit dirs and then layers
`ZEROBIN_*` environment variables on top of the settings.

**Settings resolution** (`zerobin/utils.py`): `settings` is a singleton `SettingsContainer`
seeded from `default_settings.py`. `ensure_app_context()` then:
1. Resolves `DATA_DIR` and `CONFIG_DIR` via `appdirs` (`0bin`/`tygs`) unless overridden by
   argument or `ZEROBIN_DATA_DIR` / `ZEROBIN_CONFIG_DIR`.
2. Creates `pastes/` and `sessions/` under the data dir, `custom_views/` under the config dir.
3. Generates `secret_key` in the config dir on first run. `SECRET_KEY` derives both the
   obfuscated `ADMIN_URL` (`/admin/<sha256("admin"+key)>/`) and every paste's `owner_key`
   (`sha256(key + uuid)`), so rotating it invalidates all owner keys and moves the admin URL.
4. Copies `default_settings.py` to `<CONFIG_DIR>/settings.py` on first run and executes that
   file with `runpy`, taking only UPPERCASE names. That copy, not the repo file, is what a
   deployed instance reads.
5. Prepends `<CONFIG_DIR>/custom_views` to Bottle's `TEMPLATE_PATH`, so a same-named `.tpl`
   there overrides the shipped one (this is the theming mechanism).

**Paste storage** (`zerobin/paste.py`): one plain-text file per paste at
`<DATA_DIR>/pastes/<uuid[:2]>/<uuid[2:4]>/<uuid>`, three lines: expiration, encrypted content,
JSON metadata (title, btc tip address). The uuid is a truncated base64 SHA1 of the ciphertext
(`PASTE_ID_LENGTH`, min 4). Expiration is either an ISO-ish datetime string or the literal
`burn_after_reading#<creation datetime>`; the 10-second window after creation in
`display_paste` exists so the post-create redirect does not burn the paste. A global paste
counter lives at `pastes/counter` guarded by `lockfile`. `Paste.DIR_CACHE` is a per-process
in-memory set to avoid repeated `isdir` calls.

**Client side** (`zerobin/static/js/behavior.js`, one file): a Vue 2 instance mounted on
`#app` plus a `window.zerobin` utility object. Vue delimiters are switched to `{% %}` because
Bottle templates own `{{ }}`. Crypto lives in `zerobin-crypto.js`, a DOM-free module over
the vendored `noble-ciphers.js` bundle (rebuilt from npm by `vendor_noble_ciphers.sh`).
Flow on create: generate a random 32-byte key (unpadded base64url), optionally downscale
images via canvas, encrypt with XChaCha20-Poly1305 and a fresh 24-byte nonce into
`{"v":2,"cipher":"xchacha20poly1305","nonce":...,"ct":...}`, POST form-encoded to
`/paste/create`, then redirect to `/paste/<id>#<key>`. The server rejects payloads that do
not start with that prefix as a cheap "looks encrypted" check. Pastes from the older SJCL
format (`{"iv":`) are detected client side and reported as unreadable. On display, the key is read from `location.hash` and never sent;
content is decrypted, syntax-highlighted with prettify, and the URL (with `?owner_key=`) is
stored in localStorage for the "previous pastes" menu. Owner key is what authorizes
`DELETE /paste/<id>` from the browser. Much of the DOM handling is still imperative
(migrated from jQuery), so JS is tightly coupled to element IDs and classes in the templates.

**Templates** (`zerobin/views/*.tpl`, Bottle SimpleTemplate): `base.tpl` swaps between the
minified bundles and the individual source files based on `settings.DEBUG`, and appends
`?{{ STATIC_VERSION }}`, a hash of the asset files computed at startup, for cache busting. Editing `behavior.js` or `style.css` has no visible effect
in non-debug mode until you rerun `doit compress`; both minified outputs are committed.

**Versioning**: the single source of truth is `zerobin/VERSION`, read by `zerobin/__init__.py`
and `setup.cfg` (`attr: zerobin.__version__`).
